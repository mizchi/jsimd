# @mizchi/jsimd/bitset experiment

Experimental Wasm-SIMD fixed-capacity bitset. The backing words stay in Wasm memory so repeated set
algebra does not copy through JavaScript.

```ts
import { FixedBitSet } from "@mizchi/jsimd/bitset";

using left = FixedBitSet.from(1_000_000, [1, 10, 999_999]);
using right = FixedBitSet.from(1_000_000, [10, 20]);
left.intersectionCount(right); // 1
left.unionWith(right);
```

## Recorded result

Deno 2.6.4, Apple M5, 4,194,304 bits:

| operation          | Wasm SIMD | scalar `Uint32Array` | `Set<number>` |  BigInt |
| ------------------ | --------: | -------------------: | ------------: | ------: |
| intersection count |   38.9 us |             380.1 us |       11.2 ms |     n/a |
| in-place union     |   15.3 us |             302.6 us |           n/a | 48.2 us |

Small and medium immutable unions can be faster with BigInt. This package targets large mutable
sets, cardinality, and repeated compound operations.

## Reproduce and compare

From the repository root:

```sh
pnpm bench:bitset
pnpm bench:record:bitset
pnpm bench:compare:bitset
```

The committed `benchmarks/baseline.json` records the designated Node/Vitest environment. Do not
compare absolute results generated by different machines.

Leaving the `using` scope returns storage to the package free list through `Symbol.dispose`. The
stress test creates and disposes 10,000 instances and requires `liveBytes` to return to its baseline
and `reservedBytes` to plateau.
